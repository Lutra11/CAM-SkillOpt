# FRESH：把成功、失败、前置条件和修复组织为可检索经验

> 原文：*Learning from Failures: Heterogeneous Graph Memory for Small Language Model Tool-Using Agents*。方法名 FRESH。首次提交：2026-09-23；本文依据 v1，核对日期：2026-10-21。本文为方法解读，没有训练检索器或运行作者实现。
>
> [论文页面](https://arxiv.org/abs/2609.28003) · [正文与附录](https://arxiv.org/html/2609.28003v1) · [阅读索引](README.md)

## 1. 它认为普通记忆有什么缺陷

一条失败轨迹里往往既有正确读取，也有错误写入。若整条当负例，会丢掉正确经验；若只凭语义相似把失败轨迹检索回来，又可能让模型复现错误操作。

FRESH 将经验细化到动作及其依赖：什么动作被验证过、为什么失败、缺什么条件、怎样修复。检索结果在执行时提供给冻结模型，并对特定动作做前置条件检查。[原文 Method](https://arxiv.org/html/2609.28003v1)

**它冻结的是执行 LLM，原方法还训练了辅助图检索器。** 因此“无需微调执行模型”不等于“完全无需任何训练”。

## 2. 异构图为什么重要

图包含任务、工具、动作、观察、错误、前置条件、修复等不同类型节点，以及 requires、verified_by、fails_because、fixed_by 等依赖关系。

这种组织可以将“某动作失败”和“从这个失败得到的正确警告”分开。前者是应避免的行为，后者可以是有用指导。一个动作也可以连接其成功证据、缺失检查及纠正方案。[原文 Failure-Aware Experience Graph Induction](https://arxiv.org/html/2609.28003v1)

**以下为本文构造的 SpreadsheetBench 例子：**

```text
动作：批量覆盖目标区域
  requires → 已确认真实数据边界
  fails_because → 将汇总行误作普通数据
  fixed_by → 先识别汇总行，再限制写入范围
  verified_by → 可见结构检查与训练反馈
```

这里的历史边界值不能直接复用到新工作簿；应复用的是识别与检查方法，当前数值仍要重新观察。

## 3. 离线学习流程

先从训练轨迹提取工具、参数、实体和执行结果，再做动作级经验整理。有效动作、成功修复和有用前提可以成为正例；错误动作、重复调用和不相关记忆可成为负例。

检索分两阶段：稀疏召回找相关节点并扩展有限邻域；异构 GNN 结合节点类型、关系、文本及统计特征做 query-conditioned 重排。不同关系有不同消息传递参数，让一个动作的表示吸收相关前提、错误和修复信息。

图检索器用正负节点排序目标训练，使当前查询下有用证据得分更高。原文对执行 LLM 不做参数更新，但该重排器的参数确实更新。[原文 Heterogeneous Graph Retriever Training](https://arxiv.org/html/2609.28003v1)

## 4. 在线执行为什么不是直接复制历史

检索节点被整理成四类短指导：

| 分类 | 回答的问题 |
|---|---|
| Do | 哪些操作或模式有验证支持 |
| Avoid | 哪些错误模式要避开 |
| Check | 执行前需要补哪些观察和条件 |
| Repair | 失败时有哪些已验证的修复方向 |

这份 memory sheet 受固定上下文预算约束，保留依赖而去掉无关历史。执行模型结合当前任务、历史、工具与记忆提出下一动作。[原文 Test-time Graph-Conditioned Execution](https://arxiv.org/html/2609.28003v1)

对状态改变、终止或敏感操作，gate 还会结合当前观察和规则，返回 Allow、Revise、Block 或 Transfer。历史记忆支持某动作，不代表当前前置条件已经满足。

## 5. 经验何时更新

训练与 development 阶段可以根据执行反馈更新节点 utility，并补充新错误、修复与前提，再形成检索器训练样本。

最终测试时图与检索器都冻结。这一点防止把刚完成测试任务的反馈写进记忆，再用于后续测试任务而不说明评价协议。[原文 Policy / Precondition Gate and Self-Evolution Loop](https://arxiv.org/html/2609.28003v1)

```text
训练：轨迹 → 动作/条件/修复图 → 正负监督 → 训练检索器
执行：当前上下文 → 稀疏召回 → 图重排 → 四类指导 → 动作 → 条件门控
测试：冻结图、检索器及更新规则
```

以上为教学性概括。持续在线更新可以作为另一个协议研究，不能混入冻结测试的结果。

## 6. 实验结果需要怎样解释

论文评价 τ-bench 和 AppWorld，执行模型包括 Llama-3.2-1B、Qwen3-8B、Gemma4-26B-A4B。Gemma 的 τ-bench 汇总列从 0.469 到 0.520；这列是跨域及多个可靠性指标的均值，不应称为单一 Pass@1。表中 +10.8% 是相对提升，约 +5.1 个百分点才是该汇总值的绝对变化。[原文 Experiments、表 1](https://arxiv.org/html/2609.28003v1)

τ-bench 的 pass^k 强调重复试验的可靠成功，应与常见“k 次尝试中至少成功一次”的 pass@k 区分。不同方法的记忆结构、检索训练与 gate 也共同影响效果，不能把整套提升都归给图存储。

## 7. 与 CAM 拒绝编辑记忆的本质差别

CAM 当前持久记忆主要记录被拒绝的编辑及其证据，并用于后续反思。FRESH 的经验对象是执行动作及其依赖，检索发生在求解过程，且可影响实际动作是否执行。

因此，把现有拒绝记录换成图数据库，并不自动实现 FRESH。需要动作级轨迹、当前状态查询、结构化经验提取、求解时注入和条件检查接口。

特别是代码一次生成后整体执行的模式，动作粒度并不天然等于一行 Python。若没有明确事件或工具边界，应先使用较粗的执行阶段，避免虚构精细但无法验证的动作因果关系。

## 8. 内网条件下能做到哪一步

**项目适配建议：** GLM 提取结构化经验，Qwen 执行；先用本地稀疏检索、类型筛选、邻域扩展和 utility 排序构造 memory sheet，不训练 GNN。

这条路线只需要现有推理 API，但应叫“FRESH 启发的免检索器训练变体”。完整复现则还需训练框架、文本特征与图检索模型的资源确认，不能只凭已有 LLM 端点断言具备全部条件。

建议分别比较平面经验检索、关系图但不用训练重排、加入训练重排、再加入动作 gate。对齐记忆 token、工具次数和执行轮数，才能识别关系结构的独立贡献。

这篇最值得迁移的设计是：**保存失败的原因与修复依赖，并把它们接回当前动作决策。** 这比增加更多负面警告更接近可用的执行经验系统。

## 9. 为什么不能把整条失败轨迹都当成负例

假设一次任务先正确读取用户信息，再正确定位记录，最后在没有确认资格时执行修改。整个任务失败，不代表前两步不值得复用；真正需要避免的是缺少前置条件的那次修改。

FRESH 的经验提取因此要把动作、结果和条件拆开。错误动作本身可以作为负面样本，而“修改前确认资格”的反思可以作为正面指导。二者来自同一次失败，却具有相反用途。

这类动作级归因比整轨迹评分更细，也更容易出错。执行顺序相邻并不能证明因果关系；模型推断缺少某前提，应尽量对应具体工具观察、规则或后续验证结果。[原文 Failure-Aware Experience Graph Induction](https://arxiv.org/html/2609.28003v1)

**项目适配建议：** 经验条目保存来源任务、事件范围、原始反馈和推断状态。无法从当前日志确认的原因可以保留为假设，不能直接升级成所有未来任务必须遵守的硬条件。

## 10. 图查询为什么需要当前交互状态

同一句用户请求，在刚开始执行与已经观察到错误后，最相关的经验可能不同。开始时需要规划与读取建议，错误后需要具体修复，写入前则需要检查条件。

查询不应只有任务文本，还要包含意图、实体/参数类型、可用工具、近期错误与当前观察。稀疏召回先找到语义或类型相关节点，再扩展邻居，将动作与其前提、失败原因和修复一起带入候选子图。

只检索一个“修改记录”动作节点，可能遗漏“必须确认对象身份”的依赖；全图每次编码则计算量过大。先召回再有限扩展，是在信息完整性与成本之间取得折中的办法。[原文 Query construction and sparse recall](https://arxiv.org/html/2609.28003v1)

若初始召回没有找到相关经验，后续 GNN 也不能创造缺失节点。检索失败应区分“图里没有”“召回没找到”“重排没选中”“序列化丢失”四个环节，避免全部归因于模型不遵从记忆。

## 11. 异构 GNN 的增量信息来自哪里

普通向量检索主要比较文本相似度。异构图重排还考虑节点类型、关系和邻域消息，例如某动作与多次失败相连、某修复有成功验证支持、某前置条件正是当前任务缺失的观察。

关系类型不同，消息变换也不同，因此“由这个错误引出”和“被这个结果验证”不必混成同一种相关性。经过若干层后，一个节点的表示包含其局部结构，再与查询一起进入打分网络。

这种设计的价值是使检索排序更贴近行动用途，而非只看字面相关。但层数过多或图中关系噪声很大，也可能将无关信息传播进表示。检索器需要监督与验证，不能只因用了图网络就假定优于规则检索。

**项目适配建议：** 在未训练 GNN 的第一版中，保留相同候选子图和 memory sheet 格式，仅替换重排器，才有条件比较训练重排的增量贡献。如果连经验内容也不同，就无法归因。

## 12. 训练目标与负例选择的细节

论文为查询准备有用节点 v+ 和不合适节点 v−，采用成对排序目标。其核心形式是：

```text
L_rank = −Σ log sigmoid(s(q, v+) − s(q, v−))
L_total = L_rank + λ × 参数正则项
```

目标提高正节点相对负节点的得分，而不是训练执行 LLM 输出正确动作。梯度只更新辅助检索器，冻结 LLM 仍通过输入记忆间接受益。

负例的质量很关键：随机不相关内容太容易区分，未必能教会检索器识别“文字相似但前置条件不符”的危险经验；错误动作与有用警告又不能都统一标负。正负标签必须与查询及实际反馈相联系。[原文 Feedback-derived supervision、Training objective](https://arxiv.org/html/2609.28003v1)

上述难例分析是方法层面的推论，不表示本文确认作者使用了某种额外负例挖掘策略。完整复现时应以作者代码及最终训练配置为准，缺失细节不能凭常见做法补写为论文事实。

## 13. 从检索到执行 gate 的一次完整推演

**以下为教学性的工作簿场景。** 当前请求需要删除满足条件的行，历史图里既有直接删除成功案例，也有因为未识别汇总行而误删的案例。

第一步，查询结合“删除行”意图、当前 sheet 观察与现有工具，召回相关经验。第二步，关系扩展带回范围识别、汇总行检查和误删修复。第三步，重排与序列化形成四类指导：可用操作、避免模式、必要检查和修复方向。

第四步，Qwen 提出具体写入动作。gate 根据当前观察检查是否已经确认汇总行边界；历史上确认过类似文件并不等于当前已确认。若缺少读取，返回 Revise，要求先补充观察；若参数明确违反约束则 Block；条件齐全才 Allow。

即使 Allow，也不说明最终答案正确，只说明当前检查覆盖的条件满足。写入后仍可能需要结果评价。Transfer 在原方法中对应自动处理不合适等情况；本项目若映射为强模型接管，属于额外策略，需要单独记录接管预算和判定规则。

## 14. Do/Avoid/Check/Repair 怎样避免变成长篇警告

memory sheet 的价值不在于数量，而在于当前可行动性。每条建议应对应可理解的操作、条件或修复，不应混入历史任务的具体答案、旧对象标识和无关中间输出。

例如“历史任务 X 的第 17 行不能删除”通常不可迁移；“先通过可见字段确认汇总行，再限定删除区域”才可能成为程序知识。若去掉所有具体条件，只保留“仔细检查”，又会失去经验价值。

固定上下文预算下，序列化应尽量保留依赖成组的信息：仅留下动作却裁掉前提，可能让记忆反而误导。去重、内容选择和字段裁剪都应可追踪，不能只看到检索命中就认为有效注入。

**项目适配建议：** 分别计数召回、最终选中、实际注入、模型响应引用和 gate 触发。它们代表不同机制阶段，与现有 CAM 对记忆写入、命中、注入的区分思路一致，但对象从补丁扩大到执行动作。

## 15. 原消融与本地对照能回答哪些问题

原文包含启发式检索、去掉 HGNN、去掉 policy gate、去掉失败记忆等变体，用来拆分学习检索、结构化经验和动作约束的作用。作者指出，不同任务环境对各部分的依赖不同。[原文 Ablation Study](https://arxiv.org/html/2609.28003v1)

本地最先可以做“不训练重排”的启发式变体，但不能将它的效果当成完整 FRESH。随后若训练资源就绪，再保持相同图和候选召回比较重排；保持检索结果一致比较有无 gate；保持记忆预算一致比较成功经验与成功/失败联合经验。

还应有只加普通检查规则的对照。如果一个固定前置检查已经解决大部分问题，复杂图记忆的额外收益可能很小；如果相似任务的条件变化很多，关系经验才可能体现优势。

## 16. 训练、部署与更新成本如何拆开

离线成本包括轨迹收集、结构提取、文本特征生成、图检索器训练及验证。在线成本包括查询构造、召回、图重排、提示增加和 gate。内网调用免费也仍然存在吞吐与延迟成本。

图持续变大时，检索器是否需要重新训练、旧节点统计是否仍可靠、节点合并是否破坏来源，都属于维护问题。原论文最终测试冻结图与模型，避免把这种在线更新复杂性混入评价；生产持续学习则需要另一个清楚的更新协议。

因此，FRESH 的核心不是换一个图数据库，而是建立从可验证动作经验到当前决策的完整信息路径。复现时应先确认这条路径真实工作，再判断训练检索器能否提供值得其成本的额外提升。
