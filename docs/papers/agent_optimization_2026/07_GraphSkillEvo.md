# GraphSkillEvo：图结构技能与种群进化搜索

> 原文：*GraphSkillEvo: Evolutionary Optimization of Graph-Structured Agent Skills*。首次提交：2026-09-18；本文依据 v1，核对日期：2026-10-21。本文为方法解读，没有运行作者实现。
>

## 1. 为什么它是本项目的重要近邻

GraphSkillEvo 直接以 SkillOpt 为主要对照，并包含 SpreadsheetBench、SearchQA 等现有环境。它认为技能优化的困难既来自非结构化表示，也来自单一路径的迭代改写。

因此它同时改变两件事：把技能组织成图结构自然语言产物；维护多个技能，用变异和交叉探索。**底层 LLM 和执行 harness 仍保持固定。** 它不是自动修改整个运行时代码的方案。[原文 §2—3](https://arxiv.org/html/2609.21749v1#S3)

## 2. 图结构技能实际长什么样

一个技能由全局指导和图组成。全局指导保存共用原则；节点保存某一步骤的规则；条件工作流指定何时适用及依次访问哪些节点。相邻步骤构成有向边，不同工作流可以复用节点。

这仍然是给模型阅读的自然语言指导，只是明确组织了结构。图结构不意味着存在一个自动检查并强制执行每条边的运行引擎。[原文 §3.1](https://arxiv.org/html/2609.21749v1#S3.SS1)

**以下为本文构造的表格技能示意，不是论文原样例：**

```text
全局指导：保持非目标区域；遵守约定输出位置

节点：观察结构 / 定位目标 / 生成代码 / 执行 / 检查产物 / 修复

工作流 A：适用普通单元格修改
观察结构 → 定位目标 → 生成代码 → 执行 → 检查产物

工作流 B：适用执行出现可恢复错误
执行 → 修复 → 执行 → 检查产物
```

复用“检查产物”节点可以减少多个任务情形反复写同样规则。优化器也可以修改节点或路径，而不只是在大段文字中插入新条目。

## 3. 四种进化操作分别改变什么

| 操作 | 使用的父代与证据 | 改变部分 |
|---|---|---|
| 全局指导变异 | 一个父代及失败轨迹 | 全局原则与共用说明 |
| 图结构变异 | 一个父代及失败轨迹 | 节点说明、节点增删、工作流路径 |
| 全局指导交叉 | 两个父代 | 合并有效全局指导，保留一个父代的图 |
| 图结构交叉 | 两个父代 | 重组节点与路径，保留一个父代的全局指导 |

原方法按 round-robin 轮换算子；父代选择偏向验证排名较好的技能，但保留选中其他技能的机会。**变异读取保留失败轨迹，交叉不直接输入这些反思轨迹。** 不能将交叉描述为再做一次单父代反思。[原文 §3.2](https://arxiv.org/html/2609.21749v1#S3.SS2)

## 4. 种群怎样迭代

初始化多个不同技能，先在完整验证集上评价。每一代让当前种群在同一批训练题上执行，为各技能保留有限失败记录；生成一批子代，再在完整验证集上评估。

父代和子代合并后保留验证得分最高的固定数量技能，直到代数用完，返回最终种群中最优技能。

```text
生成并验证 N 个初始技能
每一代：
    N 个技能分别执行同一批训练任务
    保留各自的失败证据
    轮换四种算子，生成 N 个子技能
    验证全部子技能
    从父代＋子代中取前 N 个
返回验证得分最高者，最终独立测试
```

这是教学性概括。精英保留能避免直接丢掉高分父代，但不能消除验证噪声、种群趋同或反复使用验证集的适应性偏差。

## 5. 参数和算力含义

原实验种群 N=4，演化 T=5 代，每代训练 batch 15 题，每个技能最多保留 5 条失败轨迹。完整验证不仅发生在初始化，还发生在每代子代生成后。

因此，计算规模不能简单写成“5 次更新”。多个种群成员要执行训练，每个子代要被验证；交叉和变异也各有提案调用。与 SkillOpt 比较时应同时报告训练执行、候选验证与提案的真实开销。[原文 §4](https://arxiv.org/html/2609.21749v1#S4)

## 6. 论文结果与真正需要关注的消融

无 harness 设置中，GPT-5.4-nano 的 SpreadsheetBench 为 SkillOpt 50.11、GraphSkillEvo 60.71，即 +10.60 个百分点；五基准平均为 56.89→60.90，即 +4.01 个百分点。LiveMath 在该模型上却从 29.56 降至 28.76，说明并非每项任务都获益。[原文 §4.1、表 1](https://arxiv.org/html/2609.21749v1#S4.SS1)

原实验执行和优化使用同一个模型，包含 GPT-5.4、GPT-5.4-nano；另有 Codex harness 设置。报告值来自重复技能优化运行，不能直接外推成 GLM 优化 Qwen 的结果。

最值得精读的是去掉图结构、去掉变异或交叉的比较：它们试图区分表示改进和搜索改进。只比较最终方法与 SkillOpt，难以知道收益究竟来自哪里。[原文 §5](https://arxiv.org/html/2609.21749v1#S5)

## 7. 怎样在内网做有解释力的适配

**项目适配建议：** GLM 生成和修改图技能，Qwen 固定执行；本地解析节点引用、工作流和结构合法性。结构解析不应依赖 Qwen 每次都返回严格 JSON。

最小对照应包含：原非结构化技能的单路径优化、图技能的单路径优化、非结构化技能的种群搜索、图技能的种群搜索。四格控制初始知识与评估预算，才能区分“图”和“种群”的贡献。

如果要加入硬执行流程，应单独作为新增干预：由运行时控制跳转，不再仅由模型阅读技能。不能把硬执行器获得的效果全部归给原论文图表示。

## 8. 对整体重构的启示与限制

该论文说明，更新对象的数据结构可以改变优化难度；保留多个候选也有利于复用互补做法。它适合作为从 SkillOpt 出发的强对照，未必适合作为“重构整个框架”的唯一终点。

如果新方案仍冻结 harness、只优化图技能，那么研究范围依然是技能优化。要进一步扩大范围，需要让程序观察、检查、恢复或调用控制成为可优化对象，并证明新增范围带来独立价值。

因此，阅读时要分别回答：图减少了哪类冗余；种群保留了什么单路径会丢失的信息；执行器究竟有没有真的遵守路径。三个问题的证据不能互相替代。

## 9. 结构化表示究竟减少了哪类搜索冗余

非结构化技能中，“检查范围后修改”和“修改前确认目标区域”可能表达同一程序关系，优化器却要在许多措辞和位置之间搜索。图技能把共享步骤单独存成节点，再由工作流指定顺序，使一部分改动直接对应程序意义。

例如三个工作流都需要输出检查，只改一个共享节点就能影响三条路径；若只希望某种任务多做一次检查，则修改那条工作流，而不必复制全部说明。这使“全局原则”“局部操作”“流程顺序”拥有不同修改入口。

但表示冗余只是部分减少。节点内部仍是自然语言，同一个步骤仍可有多种写法；过多相似节点也会重新引入重复。图的好处不在于把自然语言搜索消除了，而是把部分可复用结构显式化，便于定向修改。[原文 §3.1](https://arxiv.org/html/2609.21749v1#S3.SS1)

## 10. 用一个父代演示四种操作的区别

**以下为教学性例子，不是作者生成的技能。** 父代 A 的全局说明强调保留原始格式，节点包括观察、修改、保存；父代 B 的全局说明强调验证，节点包括结构定位、执行、重新加载和检查。

全局指导变异可以根据失败记录，在 A 中加入对公式保持的共用要求，图路径不必随之改变。图结构变异则可以在 A 的保存后加入重新加载节点，直接增加流程步骤。

全局指导交叉从 A、B 中合并互补原则，但保留一个父代图；图结构交叉则把 B 的验证路径与 A 的有效步骤重组，保留一个父代的全局说明。两种交叉有意限制改动面，避免每次同时改写所有层次。

这也带来兼容性问题：保留下来的全局说明可能提及已被删掉的步骤，新图节点也可能与旧原则冲突。结构验证可以查引用，但语义一致性还需要执行证据。父代都高分，不代表交叉子代必然高分。

## 11. 父代选择和精英保留为什么不是只复制第一名

论文先按验证适应度排序，父代采样权重与 `1/(r+N)` 成正比，再归一化。r 为排名，N 为种群规模。排名较好更易被选择，但差一些的父代仍有机会提供互补内容。

若总复制第一名，种群很快趋同，交叉就失去意义。若完全均匀选择，又可能频繁使用较差候选。按排名而非原始分数采样，还避免了不同任务分数尺度直接改变选择压力。[原文 §3.2、附录 B.4](https://arxiv.org/html/2609.21749v1#S3.SS2)

子代评估后，从父代与子代合集中取前 N 个，是精英式筛选。它保证当前已测得的高适应度个体不会因为一轮差子代全部丢失，但不能证明真实期望得分单调提高，原因是验证有限且执行有随机性。

如果两个个体分数相同、文字不同却行为相同，仅按适应度保留也可能浪费种群容量。额外的去重、多样性奖励或平分规则可以成为扩展，但不应未经说明混入原方法复现。

## 12. 结构合法性检查与再生成的真实作用

附录中的 validator 检查技能是否符合图 schema、工作流引用的节点是否定义、声明节点是否至少被某工作流使用。失败候选被丢弃并重新生成。[原文附录 B.3](https://arxiv.org/html/2609.21749v1)

这些检查只能证明形式一致：一个工作流可以引用正确节点，却在逻辑上先写入再读取。这样的技能结构合法、程序意义却可能错误，必须通过执行评价发现。

**项目适配建议：** 记录失败的具体原因和再生成次数。若内网 GLM 经常漏字段，协议质量会消耗大量时间；若验证器过宽，格式混乱又可能在实际渲染时改变含义。固定解析与序列化器比让执行模型自行理解不稳定 JSON 更可靠。

有限重试可避免某个候选无限阻塞，但它是运行协议选择。原算法中的再生成循环不等于实验中失败生成没有成本，也不能把所有再生成请求从提案计量中删掉。

## 13. 一代搜索的任务量怎样计算

以原默认 N=4、T=5、B=15 为例，在不考虑基础设施重试和实现额外缓存的概念性计算下，训练阶段共有 `N×T×B=300` 次任务执行。它表示执行次数，不表示 300 道唯一训练题，因为不同代可能重新采到同一题。

初始四个技能要验证，五代每代四个新技能也要验证，所以候选验证次数为 `N×(T+1)=24`。若完整验证集有 V 道题，对应约 `24V` 次验证任务执行，外加最终测试及生成调用。

这个计算解释了为什么不能只用“代数少”判断便宜。较小种群可能每轮探索不足，较大种群会扩大训练和验证开销。与现有 SkillOpt 比较时，应对齐总预算或报告随预算变化的效果曲线，而不只使用相同 epoch 数。

失败轨迹上限 K=5 也只是每个个体提供给变异的反思信息量，不是本代只允许失败五题，更不是将其他失败计为成功。执行、评分与反思抽样应分别记录。

## 14. 原论文消融应怎样理解

去掉图结构，仍保留种群搜索，可以检验表示是否独立有用；去掉交叉，仍有多条变异路径，可以检验候选间信息交换；去掉变异，保留交叉，可以检验真实执行反馈是否必要。

原文在去掉某类操作时仍生成相同数量子代，通过剩余操作轮换保持代规模。因此它试图控制“少了一类操作就少生成候选”的直接混淆。[原文 §5.2](https://arxiv.org/html/2609.21749v1#S5.SS2)

解读具体分数时还需检查表格覆盖的任务子集，不能将某个消融平均值与主表五基准平均值直接相减。不同集合上的均值回答不同问题，表头与模型设置必须一并保留。

对本项目复现，建议增加图内容等价的平面化对照：保留同样规则与路径信息，仅改变组织形式。否则图版本如果同时写入更多领域知识，观察到的差异可能来自内容增加，而不只是结构。

## 15. 跨模型迁移能说明什么，不能说明什么

论文把 nano 上优化的技能交给较强模型执行，研究程序性知识能否脱离原执行模型继续发挥作用。这是冻结模型下外部产物的迁移，不涉及模型权重合并或蒸馏。

**项目适配建议：** 可以先在 Qwen 上选择技能，再在 GLM 或 Gemma 上原样测试。迁移时应固定技能内容、渲染格式和任务定义；如果为了目标模型重新改写技能，那属于适配，不能继续称作原样迁移。

不同模型可能需要不同细节粒度。弱模型依赖明确步骤，强模型可能受冗长规则干扰，因此迁移有效不意味着同一文档对全部模型最优。应同时测不带技能、目标模型本地优化、源模型技能迁移，区分知识可用性与最优性。

## 16. 将图技能变成真正执行框架，还缺哪一层

若希望运行时严格维护流程，需要新增状态对象、节点输入输出、条件解析和跳转执行；这些都超出了把图技能写进提示词的原方法。图形式只是知识表示，运行语义需要另一层明确实现。

可以把这种扩展作为研究问题：在相同图知识下，模型自由阅读与运行时控制分别表现如何。强制结构可能降低步骤遗漏，也可能限制模型处理图外新情形，不能预先断言一定更好。

因此，GraphSkillEvo 对整体重构最具体的价值，是为可优化程序知识和多候选复用提供一个强起点；如果进一步优化执行器，必须把新增层的作用与原图技能收益分开验证。
