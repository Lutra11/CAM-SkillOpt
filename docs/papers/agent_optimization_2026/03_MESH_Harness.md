# MESH-Harness：用组合搜索和轨迹反馈优化完整执行框架

> 原文：*MESH-Harness: Self-Improving Agent Harnesses via Bandit-Guided Compositional Evolution*。首次提交：2026-10-04；本文依据 v1，核对日期：2026-10-21。本文为方法解读，没有运行作者实现。
>
> [论文页面](https://arxiv.org/abs/2610.05300) · [正文与附录](https://arxiv.org/html/2610.05300v1) · [阅读索引](README.md)

## 1. 它解决的框架优化难题

把整个框架当成一个程序反复重写，容易丢掉旧版本中仍然有效的设计；把所有可替换实现组合起来穷举，又会遇到组合爆炸。MESH-Harness 将两件事分开：**生成新的组件实现，以及决定哪种完整组合值得实际运行评估**。[原文 §3—4](https://arxiv.org/html/2610.05300v1#S4)

如果有 k 个功能位置，每个位置 N 个实现，候选组合数量为 N 的 k 次方。论文不为每个新组件立刻运行任务，而是先把它放进池，再让搜索过程安排评估。

## 2. 表示方式：固定职责接口、可替换实现

每个 slot 对应检索、上下文构造、失败恢复等功能职责，内部可以包含分支或循环，并不等于一个模型调用节点。完整框架从每个 slot 选一个实现组成。

新实现需要通过接口与基本执行检查，并排除重复。固定编码器将组件职责、接口和实现摘要转成向量；组合特征按 slot 顺序拼接，确保相同位置的特征意义保持一致。[原文 §4.1](https://arxiv.org/html/2610.05300v1#S4.SS1)

这带来跨组合复用：旧轮次发现的检索器可以与新轮次的恢复器配对，不必让 LLM 再重写整套程序。

## 3. Bandit 究竟在选择什么

一次 bandit pull 选择的是**完整框架组合**。评估后得到的是该组合的端到端分数，不是每个组件的独立收益标签。

论文维护线性奖励模型及完整信息矩阵，用组合特征预测均值与不确定性。其选择分数还考虑组件覆盖、近亲实现相似度和近期谱系重复使用，兼顾利用与探索。完整协方差用于联合估计和组合层面的不确定性；**预测均值仍然按 slot 加性分解，不能将其说成显式学习任意非线性交互**。[原文 §4.2、附录 A](https://arxiv.org/html/2610.05300v1#S4.SS2)

教学性地说，搜索偏好“预测较好、值得探索、尚未充分使用且不只是旧谱系轻微改写”的组合。这些选择信号不等于新候选已被证明更优。

## 4. 怎样避免穷举组合

每轮从当前最佳、历史优秀组合或随机组合之一开始，依次尝试替换各个 slot，用代理分数做坐标上升。

这些尝试只计算预测值，不执行任务。若发现已经评估过的组合，还会尝试寻找未评估候选。最后选中的完整框架才消耗真实任务评估预算。

```text
建立各功能位置的候选实现池
重复到评估预算用完：
    用预测模型及探索奖励选一个完整组合
    实际运行这个组合，记录分数、轨迹与资源
    更新共享统计量与候选档案
    按预定间隔从失败轨迹生成局部新实现
    将有效新实现加入相应池，淘汰低保留价值实现
冻结验证集选出的最终组合，再测试
```

以上是教学性概括。代理计算节省的是组合枚举时的实际评估，不能消除最终运行的必要性。

## 5. 组件池怎样继续演化

论文定期依据失败类型、重复错误和谱系修改记录诊断需要更新的 slot，结合修复、探索和局部精炼产生子实现。更新保持池容量固定。

淘汰依据是包含该实现的历史组合平均奖励等保留规则，并保护当前最佳组合相关实现。未评估子代不会继承父代的实测分数；它被加入池后何时参与真实评估，由后续搜索决定。[原文 §4.3](https://arxiv.org/html/2610.05300v1#S4.SS3)

因此，“通过接口检查”“进入候选池”“成为最终部署组合”是不同状态，不能都记成一次性能接受。

## 6. 原实验的预算与结果

原实验固定执行模型，优化方法各使用 40 次完整候选评估。提案器为 Claude Code / Claude Opus 5，执行器主要为关闭 thinking 的 DeepSeek V4 Flash；编码器是 Qwen3-Embedding-8B。每个 slot 初始 10 个实现。[原文 §5.1](https://arxiv.org/html/2610.05300v1#S5.SS1)

相对 Meta-Harness，四个汇总指标分别报告 +5.70、+7.01、+2.00、+5.00 分。它们对应文本分类、数学、LiveCodeBench 与 ScienceWorld，各自指标不同。表中三个 test runs 是同一冻结框架的重复执行，不能等同于三次独立完成框架搜索。[原文 §5.2](https://arxiv.org/html/2610.05300v1#S5.SS2)

评估次数相同也不意味着所有开销完全相同：组件初始化、编码、提案和执行 token 都需要另行计量。

## 7. 用 SpreadsheetBench 解释组合互补

**以下为本文构造的例子。** 观察 slot 可选“固定预览”或“按区域摘要”，验证 slot 可选“仅检查文件存在”或“重新加载检查结构”，恢复 slot 可选“异常重试”或“按失败阶段修复”。

区域摘要可能配合重新加载检查更有效；若每次恢复都重复发送完整工作簿摘要，也可能显著增加开销。组合收益必须以完整执行测量，不能只按组件单独描述推断。

这个例子还说明其接口设计的限制：若 slot 之间传递状态不兼容，所谓任意组合就无法运行。组件拆分必须先约定输入、输出和可见状态。

## 8. 内网适配与研究边界

**项目适配建议：** GLM 负责候选代码与摘要，Qwen 固定执行，先用少量 slot 和每个 2—3 个实现验证组合机制。标准线性代数和 bandit 统计量可在本地计算，不需要训练 LLM。

固定编码器仍是额外依赖。需要确认网关 embedding 能力与版本；若改用 one-hot 或手工特征，应明确叫“特征替代变体”，不能把作者依赖直接略去。

建议对照随机组合、固定池的 bandit 搜索、带新组件演化的搜索，以及整程序修改。各臂对齐候选评估预算，再分别报告提案、编码与求解开销。

它对本项目最大的启示是让旧发现可以重新组合，并把昂贵评估当作需要分配的资源。它不直接回答怎样自动发明最佳接口划分，也不保证找到全局最优组合；slot 设计和线性代理适用性都需要单独检查。

## 9. 从组件表示推到组合分数

设第 j 个 slot 选出的实现为 c_j，固定编码器给出 d 维表示 e(c_j)。完整组合 h 的特征是这些表示按位置拼接：

```text
x(h) = [e(c_1); e(c_2); ...; e(c_k)]
特征维度 p = k × d
```

顺序不能随意交换。检索器和恢复器即使都包含“错误处理”字样，也属于不同职责；按 slot 排列让模型分别学习各职责块中的特征与端到端奖励的关系。

编码器固定有利于保持历史可比。如果中途换编码器，旧特征与新特征可能不在同一空间，统计量就不能直接继续使用。新代码生成后也应重新编码，不能因为继承同一父代就复用父向量。

表示包含实现摘要，因此摘要质量会影响代理模型。摘要遗漏关键分支时，两个行为差别很大的组件可能看起来相似；换句话说，编码缓存节省调用，却引入了表示是否忠实的问题。论文的组合评估仍是最终依据，不能只按向量相似度判断代码等价。[原文 §4.1](https://arxiv.org/html/2610.05300v1#S4.SS1)

## 10. 线性模型与完整协方差怎样工作

用 x_s 表示第 s 个实际评估组合的特征，r_s 表示其分数。论文维护：

```text
A = λI + Σ x_s x_s^T
b = Σ r_s x_s
θ = A^(-1)b
预测均值 μ(h) = x(h)^T θ
不确定性 σ(h) = sqrt(x(h)^T A^(-1) x(h))
```

λ 是正则项，限制少量观测下的估计不稳定。实际求解线性系统时可采用数值稳定的方法，不要求每轮显式计算矩阵逆；这是工程实现选择，不改变上述统计目标。

完整 A 记录不同 slot 特征在组合中的共同出现，因此一次观测可以改变其他未运行组合的估计及不确定性。它与每个组件单独维护一个平均分不同：后者很难判断一个新组合的共同覆盖情况。

但均值仍是线性点积。若某恢复器只有与某验证器搭配才有效，而这种条件依赖不能由现有特征线性表达，代理可能预测不准。协方差提供的是参数估计与探索方面的联系，不会凭空加入任意交互项。应通过代理预测误差和真实组合差异来判断这种限制是否严重。[原文 §4.2、附录 A](https://arxiv.org/html/2610.05300v1#S4.SS2)

## 11. 为什么选择分数不只是一项 UCB

论文在预测均值上加探索奖励，并用组件覆盖和谱系重复情况调整选择。可以把它理解为四种压力：倾向已知好组合；给证据不足的组合机会；补足少用组件；限制连续选择同一家族的轻微变体。

相似度调节也有具体目的。一个新组件虽然从未运行，但与已评估父代几乎一样，若一律给予最高探索奖励，搜索会把预算浪费在近乎重复的实现上。相似性越高，探索加成可能被压低，但仍保留最小探索水平。

这些修正只改变“选谁去评估”，不改变实际奖励记录。不能把探索奖励加到任务正确率上，也不能把高 UCB 组合写成已验证最佳。最终部署候选仍应根据预定验证标准选择。

实际复现时应分别记录均值、探索项、覆盖项与谱系惩罚。否则当系统反复选了一个低分家族，无法判断是在合理探索，还是某一奖励项失控。

## 12. 用小型组合空间推演一次搜索

**以下完全为教学例子，数字不是论文结果。** 假设三个 slot 分别负责观察、检查、恢复，各有三个实现，理论上有 27 个组合。

已经评估过“固定观察＋文件存在检查＋普通重试”和“区域观察＋结构检查＋普通重试”。新一轮代理认为区域观察较好，但按错误阶段恢复仍缺少评估，于是从当前最佳出发尝试替换。

坐标搜索先固定后两个 slot，比较三种观察实现；再固定其他位置比较检查器；最后比较恢复器。每个比较只算代理分数，因此一轮扫描没有执行 9 次任务评估。选中的一个完整组合才真正运行。

假设新组合改善，但分析发现恢复器几乎没有触发，主要收益来自区域观察。此时不能给恢复器独立记一次“改善奖励”。系统只观察到组合分数，单组件作用需要通过更换该组件的配对对照进一步识别。

再过若干评估，失败组显示结构检查经常误判空白尾行。提案器生成新检查器，入池后没有立即得分；后续组合选择才决定什么时候用它。这样把“产生想法”和“为想法付出验证成本”分开。

## 13. 固定容量池的淘汰为什么也会影响学习

一个实现常出现在高分组合中，不一定说明它自身优秀，可能是搭档强。论文用包含该实现的历史组合平均奖励作为保留依据之一，这是可计算的经验启发式，不是无偏的组件因果贡献。

未评估候选的保留值为零，又不能继承父代结果，因此如何保护新发现并安排覆盖很关键。当前最佳实现被保护，可以避免更新池时破坏已知可部署方案；历史源码与谱系仍归档，便于追溯。

**项目适配建议：** 除池成员表，还需保存内容哈希、父代、生成轮次、被哪些组合使用、淘汰原因和可恢复的历史快照。已淘汰实现仍被历史最优组合引用时，应能恢复其准确内容，不能只保存一个已失效的列表下标。

池过小可能丢失互补组件，池过大则使覆盖变差。这个取舍应通过固定评估预算下的池规模对照来测，而不是认定候选越多越好。

## 14. 对整体架构和预算计量的要求

**项目适配建议：** 每个 slot 都应有稳定输入、输出与错误语义，例如观察器返回可序列化观察，检查器返回结构化发现，恢复器返回下一步决策。跨组件共享状态必须显式传递；若依赖未声明的全局变量，组合替换容易失败。

预算至少分为四层：初始化候选、编码、离线提案、任务评估。最终部署则只运行被选择组合的执行路径。论文报告搜索与部署成本时也区分这些用途，不能只统计被选中候选的最后一轮。

同样是 40 次候选评价，若某方法每次允许八次求解，另一方法只允许一次，并不意味着执行计算相等。评价次数用于衡量外层搜索资源，模型调用和 token 用于描述内层求解资源，两者都应公开。

## 15. 最有解释力的消融与失效信号

可以按以下顺序增加机制：随机组合固定池；预测均值选择；加入不确定性探索；加入覆盖与谱系调节；最后允许轨迹生成新组件。每一步保持其他条件一致，观察达到某验证水平需要多少真实评估。

如果随机组合已经同样好，代理可能没有提供价值；如果固定池搜索很强而新组件无增益，瓶颈可能是提案质量或池淘汰；如果预测一直偏爱未运行近亲，可能是相似度或覆盖项需要诊断。若所有合法组合都表现接近，slot 的行为差异本身可能不足。

应同时画出真实最好验证分、代理预测误差、池多样性和实际评估覆盖随轮次的变化。仅给最后一个正确率，无法判断是搜索学到了什么，还是碰巧找到一个初始强组件。

这篇最重要的工程视角是让候选实现成为能保存、组合和再利用的资产，而真实评估成为按信息价值分配的资源。

## 16. 首先检查“可组合”是否真的成立

**项目适配建议：** 在接入 bandit 之前，先用 stub 输入验证每个实现都遵循 slot 契约，再选取跨父代、跨轮次的组合执行离线检查。单个组件可运行，并不意味着与另一个来源的组件连接后仍正确。

尤其需要检查状态所有权：观察器是否修改共享输入，检查器是否偷偷重写产物，恢复器是否沿用前一轮已经失效的文件句柄。若这些副作用没有声明，代理模型学到的分数会混入不可重复的运行状态。

将接口错误、组合协议错误与任务语义失败分开记录，有助于识别当前瓶颈。前两类应先改善组件契约；只有组合稳定可运行后，选择算法的预测与探索效果才具有可解释性。
