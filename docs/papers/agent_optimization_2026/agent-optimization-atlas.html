结构化提案

GLM

轨迹分析、框架提案、局部代码生成；可尝试承担指导或偏好评审。

关键核验：输出协议、提案质量、评审校准。
主要执行器

Qwen

固定执行模型，观察框架改变是否带来更好的实际任务行为。

关键核验：工具协议、检查遵从、调用预算。
迁移验证

Gemma

作为第二执行模型，检验程序知识与通用运行机制能否迁移。

关键核验：实际模型身份、输出与工具稳定性。

ADAPT /逐篇查看实现边界

冻结执行模型，与整个系统无需任何训练，是两个命题。

CONTROL /让改进有可解释的证据

固定执行模型

更强模型、更多尝试与更好框架策略分别比较，避免将 GLM 接管带来的收益归给调度。

预算分层计量

区分离线提案、编码/训练、候选验证和最终求解；免费调用同样消耗吞吐与时间。

保留隔离测试

参与晋升的数据承担验证角色。最终测试不用于改阈值、选版本或重新设计框架。

旧记录中 minimax 别名映射至 Qwen，聚合路由身份不稳定，不能仅按别名算成独立模型。具体参数兼容性与可用性应在正式实验前重新核验。
